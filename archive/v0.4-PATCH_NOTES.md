# Kata config-digest prototype v0.4

## What we found in current Kata source

The exact in-guest handoff is `src/agent/src/rpc.rs`,
`AgentService::do_create_container()`.

`CreateContainerRequest.OCI` is converted into an `oci_spec::runtime::Spec`.
The agent then mutates that spec in-guest through device handling, CDI handling,
trusted/sealed storage handling, namespace updates and guest-hook injection.

The best initial config-digest hook is therefore immediately after:

```rust
update_container_namespaces(&s, &mut oci, use_sandbox_pidns)?;
append_guest_hooks(&s, &mut oci)?;
```

and before:

```rust
let olddir = setup_bundle(&cid, &mut oci)?;
```

At that point the digest represents the OCI runtime state the measured agent is
about to materialize into the bundle and pass to `LinuxContainer`.

## Image identity is a separate input

For guest-pull, the image is represented as an `image_guest_pull` Storage
object and `ImagePullHandler` invokes Confidential Data Hub from inside the
guest. The current CDH client API returns success/path, not a resolved digest.

For our first Akash test this is manageable because the SDL is already pinned
to an immutable `@sha256:...` reference. For a general protocol, the measured
guest-pull path should expose the *resolved* manifest digest from the CDH/image
pull implementation rather than trusting a tag or tenant claim.

Do not concatenate a self-reported image digest with `config_digest` and call
that attested identity.

## Next binding

Once we can obtain:

- `image_digest` from measured guest-pull state;
- `config_digest` from this measured kata-agent hook;
- `workload_pubkey` generated inside the confidential guest; and
- a fresh `nonce` supplied by the external verifier/KMS,

the target commitment is:

```text
H(
  domain_separator ||
  workload_pubkey ||
  image_digest ||
  config_digest ||
  nonce
)
```

That commitment then needs to be covered by fresh platform attestation or a
measured-agent authenticated statement that Trustee/KBS can verify.

## Important prototype limitations

This patch is a review prototype, not an upstream-ready Kata patch.

- It has not been compiled against the full Kata tree in this environment.
- The environment-variable policy is not finalized.
- Mount source canonicalization needs policy treatment.
- Runtime mutations that occur *after* this hook must be reviewed.
- The digest is only logged in this prototype; logs are not a trust channel.
- We still need the image-pull/CDH resolved digest and attestation binding.

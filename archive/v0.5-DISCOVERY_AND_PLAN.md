# v0.5 discovery: the resolved image digest already exists

The key finding is better than expected.

Current `confidential-containers/guest-components` already defines:

```proto
message ImagePullResponse {
    string manifest_digest = 1;
}
```

Its CDH server obtains that digest from `Hub::pull_image()`, and `Hub::pull_image()` obtains it from `image-rs::ImageClient::pull_image()`. `image-rs` returns an `ImageInfo` containing both `config_digest` and `manifest_digest` after it has resolved and pulled the manifest.

Even more importantly, CDH already calls Attestation Agent `ExtendRuntimeMeasurement` for the image pull event with content containing the image URL and the resolved manifest digest.

So we do **not** need to invent trusted image-digest acquisition. We need to bridge an API-version gap in Kata: the Kata-local `confidential_data_hub.proto` still has an empty `ImagePullResponse {}`, and Kata's CDH client discards the reply.

## v0.5 plan

1. Add `manifest_digest = 1` to Kata's local CDH proto, matching current guest-components.
2. Return the digest through Kata's CDH client.
3. Carry it through `ImagePullHandler` / `add_storages()` into `do_create_container()`.
4. Compute our canonical `config_digest` after Kata's in-guest OCI mutations.
5. Treat `(manifest_digest, config_digest)` as the measured workload identity inputs.
6. Next, extend a second Attestation Agent runtime measurement for the config digest.
7. Bind both to a fresh verifier nonce and an in-TEE workload public key.

## Trust model improvement

Do not trust `IMAGE_ID`, tags, or a digest supplied by the tenant container.

For guest-pull:

```text
registry
  -> image-rs resolves manifest
  -> image-rs returns manifest_digest
  -> CDH returns manifest_digest
  -> CDH already extends PullImage runtime measurement
  -> Kata receives same manifest_digest
  -> Kata computes resolved config_digest
```

The remaining attestation gap is the config digest / key / nonce binding, not image resolution.

## Important implementation note

This is still a review patch, not a compile-tested upstream patch. In particular, changing `add_storages()`'s return type should be compiled against the full Kata tree and its tests before use.

# Kata / CoCo workload-bound evidence v0.6

This prototype binds four values into fresh TEE evidence:

1. resolved OCI manifest digest from in-guest `image-rs` / CDH;
2. canonical resolved runtime `config_digest` from measured `kata-agent`;
3. ephemeral workload public key generated in the confidential guest;
4. fresh verifier/KMS nonce.

The commitment is:

```text
SHA256(
  domain ||
  len(pubkey) || pubkey ||
  len(image_digest) || image_digest ||
  len(config_digest) || config_digest ||
  len(nonce) || nonce
)
```

The 32-byte commitment is supplied to Confidential Containers Attestation
Agent `GetEvidence(RuntimeData=...)`.

For current SEV-SNP attester code, `RuntimeData` is passed to
`SnpAttester::get_evidence()`, which allows at most 64 bytes, pads to 64 bytes,
and passes that buffer to the SEV guest firmware as report data. Thus the
verifier can require:

```text
REPORT_DATA == commitment || 32 zero bytes
```

## Critical design rule

Runtime-measurement/event-log extension and fresh REPORT_DATA binding solve
different problems. The image pull event log is useful provenance, but for the
per-request KMS challenge we use fresh `GetEvidence(RuntimeData)` so nonce and
workload key are covered by the newly generated SNP report.

## Still not production ready

This package is an architecture + patch prototype. It deliberately leaves the
challenge transport/API integration explicit rather than faking it with env
vars. The next implementation task is to add an authenticated challenge RPC
between the external verifier/KMS and the measured in-guest component, then
return `WorkloadEvidenceResponse` to the verifier.

The verifier must additionally validate the full SNP certificate/TCB/reference
chain, Init-Data/policy, GPU evidence where required, and any ZK build-policy
proof before releasing a secret. Secret output should be encrypted/wrapped to
the attested workload public key.
